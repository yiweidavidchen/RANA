# Structure-review methods and verification

## Sources and sequence identity

Exact inputs and retrieval timestamps/hashes are in [source_manifest.json](source_manifest.json).
All coordinates and downloaded HTML/JSON remain in `data/processed/m6_bglb_structure_review_2026-10-25/sources/`.
The attachment was copied byte-for-byte without modifying the original.
PDB/CIF validity was checked before archival; RCSB mmCIF and JSON were parsed,
and the source PDBs contain valid ATOM records. The public D2D PDB and attachment
are byte-identical. A resource-page FASTA link returned 404 and is recorded as
unavailable, not accepted as sequence data.

Extract coordinate residues from fixed-column ATOM records, preserving chain,
number, insertion code and parent. Canonical heavy-atom name sets check the
observed residues; optional terminal OXT and all hydrogens are excluded from
the required-atom checklist. “None missing” is a modeled-residue atom check,
not a claim of full-construct coverage. RCSB missing-residue/atom categories,
altloc/occupancy records, assemblies/operators and refinement software are
retained in the curated audit. No experimental method/resolution is transferred
from a similar structure onto the D2D file.

The D2D HTML `<big>` sequence equals `P22505.json:sequence.value` (448 residues).
Align each complete coordinate sequence to this reference with Biopython
PairwiseAligner, global mode, match 2, mismatch -1, gap-open -10, gap-extend -0.5.
These are sequence-audit settings, not RANA scientific parameters. Each optimal
alignment is unique and covers every observed residue. Use that alignment for
all 445 mappings per input and check the 13 functional/background sites against
the page's explicit Rosetta/Foldit/PDB tooltip strings. No +3 offset is assumed
for an input file. RCSB full SEQRES/entity sequences remain separate from the
coordinate sequences and from the 448-residue public standard.

## Atom matching and coordinate differences

Match by aligned reference position, same parent, atom name, altloc and element.
Reject duplicate identities. Exclude H/D and, for 2O9P comparisons, unlike-parent
positions 376/377. Do not mutate, rename, complete or relax atoms to force a match.
Record unmatched identity counts. Fit each heavy-atom/Cα/backbone subset using
NumPy SVD of centered X-transpose-Y, enforcing a proper rotation (determinant +1).
With row vectors, aligned X is `X @ R + t`; report raw and fitted RMSD and the
maximum residual. A synthetic rotation/translation check recovered RMSD below
1e-12 Å. Maximum Cα inter-residue distance differences independently test rigid
motion invariance without relying on a fit.

The PDBs serialize coordinates to 0.001 Å. Use conservative compatibility bounds
of fitted RMSD <=0.002 Å and maximum residual <=0.004 Å for a rigid transform plus
rounding; these bounds classify correspondence, not quality or model provenance.
All three comparisons exceed them substantially. Heavy-atom names may include
symmetry/rotamer differences, so the separate Cα/backbone and invariant-distance
checks matter. Background/ligand differences are not isolated conformational
effects, and coordinate proximity does not establish the preparation history.

## Ligand and annotation limits

LG1 composition is a direct element census. The maintainer's pNPG assignment
is consistent with C12H15NO8 and public CCD PNW. Neutral RDKit bond-order and
stereochemistry inference from the supplied coordinates failed; preserve the
exact error and null result. No alternate charge, forced template assignment,
bond repair or coordinate optimization was used to obtain a desired answer.
This is chemical support for a reported holo candidate, not independent evidence
of beta stereochemistry, experimental binding, occupancy or a new crystal structure.
UniProt functional feature evidence codes are retained without upgrading their
evidence level. No experimental pAzF data enter this review.

## Actual execution level

Inspection used Python 3.13.12, NumPy 2.5.4,
Biopython 1.88 and RDKit 2026.9.1 in the existing
development environment. The local script `data/processed/m6_bglb_structure_review_2026-10-25/audit_inputs.py` has
SHA-256 `d9ceace75d469e178f4b25824e411f13516d9e3852cde01a45df6854e902236b`. Its completed audit is under
`audit_completed/`; the first attempt stopped at the optional neutral-ligand
inference, and the completed record explicitly retains that unresolved result.
No new dependencies were installed for the structure review. No RANA scoring,
scan, relaxation or new experimental analysis ran in that earlier review phase,
and no scan-ready coordinates were generated by that review.
The full scientific pytest suite is not required for these new data/documents;
validation instead checks source hashes, sequence/identity joins, all requested
parent identities, table/JSON consistency, assembly operators, rigid-fit sanity,
file preservation, public-file boundaries and whitespace.

## Subsequent accepted execution

The later single-input scan and post-scoring curation are documented separately
in [reproduction.md](reproduction.md), [results_report.md](results_report.md) and
[execution_summary.json](execution_summary.json). The original review data and
sources were retained. Runtime checks use explicit exceptions, not assertions;
targeted tests cover output integrity, annotation separation, tie handling and
normal/optimized Python failures. This does not upgrade the review or scan to
experimental predictive validation.
